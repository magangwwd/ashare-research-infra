# BTC Regime Router V1 — 2026-10-16

## 目标

本模块不回答“BTC 明天涨还是跌”，而回答更重要的问题：

> 当前 BTC 处于什么运行周期？这个周期下，哪一类策略的风险收益结构最匹配？什么时候必须切换？

因此，策略本身与**策略选择器**分离。现有冻结的 V3 不修改；HMG 也是独立候选。只有当路由器经过历史样本外验证后，才考虑进入更高等级的影子测试。

## 1. 周期识别

使用五类信息：

1. 30/90/180 日收益方向投票；
2. 60 日 Efficiency Ratio 判断趋势还是来回震荡；
3. 60 日实现波动率 + 14 日 ATR/Price + 波动率历史百分位；
4. EMA200 与其 30 日斜率作为长期锚；
5. 120 日价格区间位置与宽度作为辅助。

关键思想是：**趋势、波动、区间属性必须同时判断，不能用单一均线决定策略。**

## 2. 周期 → 策略

| Regime | 推荐 | 允许网格 | 处理 |
|---|---|---:|---|
| TREND_UP | V3 | 否 | 顺势 |
| RANGE | HMG | 是 | 均值回归 |
| RECOVERY | V3_DEFENSIVE | 否 | 恢复期低风险 |
| TREND_DOWN | CASH | 否 | 不逆势补仓 |
| HIGH_VOL | CASH | 否 | 风险关闭 |
| TRANSITION | CASH | 否 | 等待确认 |

HMG 上限：

- 账户最大网格资金 25%
- 最多 5 层
- 加仓倍率 1.00 / 1.15 / 1.25 / 1.35 / 1.50
- 网格间距 0.9 × ATR14，并限制在价格的 1.8%～3.5%
- 篮子止盈 +0.8%
- 账户回撤 ≥8%：停止新网格并降低风险
- 账户回撤 ≥15%：全局停止并清仓
- 无杠杆、只做现货多头

## 3. 历史数据如何验证“周期 → 策略”

不能把全历史一次性回测后，再挑一个最好看的参数。

采用严格 Walk-Forward：

- 训练：过去 730 个完成日；
- 测试：未来 90 个完成日；
- 每 90 天重新估计一次“每个 Regime 下最稳健的候选策略”；
- 测试窗口内冻结映射和参数；
- 一直滚动到最新完整数据。

每个 Regime 至少检查：

- 年化收益 / CAGR
- 最大回撤
- Calmar / Sharpe
- 20 日前向收益中位数
- 前向亏损概率
- 最大连续亏损
- 最大资金占用
- 成交次数/换手
- 1×、2×成本压力测试

**收益不是唯一排序指标。** 对本系统，回撤、尾部风险和资金占用优先级更高。

## 4. 实际交易中的及时修正

### 每个 UTC 日线收盘后

1. 校验数据完整性；
2. 计算最新 Regime；
3. 检查账户回撤；
4. 检查 HMG 层数；
5. 生成下一交易日策略建议。

### 切换规则

- HIGH_VOL / TREND_DOWN：一个完成日即可进入风险关闭；
- 普通状态切换：连续 2 个完成日确认；
- 普通状态至少保持 7 日，减少来回切换；
- 从风险关闭恢复：连续 3 日确认。

### 绝不采用

- 因最近几天亏损就临时调参；
- 使用未来价格修改历史 Regime；
- 为追求月化 2%～5% 放宽仓位；
- RANGE 失效后继续补网格；
- 把历史相似阶段当成未来必然复制。

## 5. 当前 BTC 应用

2026-10-15/16 的公开价格约 82K。Glassnode 最新研究把 BTC 描述为“boxed in”：约 80K～81.5K 为重要支撑重叠区，约 78K 为更深的结构支撑，88K 附近为明显上方供应/成本区。其更长周期判断偏向熊市后的早期恢复，但短期仍是箱体而非已确认主升。

因此，本版本当前候选优先级：

**RANGE / RECOVERY → HMG 小仓位候选；TREND_UP 确认后才切 V3；跌入 HIGH_VOL/TREND_DOWN 则现金。**

最终以仓库用最新可信 Binance UTC 日线跑出的结果为准，不用 ChatGPT 手工替代程序信号。

## 6. 数据与安全

- 主研究数据：Binance Spot BTCUSDT UTC 1D；
- 当前市场状态可用 OKX 公共价格页交叉核对；
- Binance 公共市场数据接口不需要 API Key；
- 本项目仍保持研究模式，不连接交易密钥、不发送真实订单；
- 原 4H 缺口问题保持独立，不能用 1D 替代数据声称 4H 已修复。
