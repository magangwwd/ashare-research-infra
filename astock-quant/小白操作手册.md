# A 股量化项目小白操作手册

> 本项目输出只用于量化研究、筛选和复盘，不是投资建议，也不是实盘成交确认。

## 一、先记住三句话

1. 最新报告只看 `financial_data/reports/` 里的归档报告，不看旧的 `financial_data/report.md`。
2. 不要在 A 股交易时间运行 `update_daily.py`，当天数据可能还没收盘；脚本会在工作日 09:15-15:05 自动拒绝运行。
3. 看到 `no_trade`、`市场阻断观察`、`过热观察`，意思是不要直接当买入信号。

## 二、每天最常用流程

### 1. 打开命令行并进入项目目录

在 PowerShell 里运行：

```powershell
cd "G:\我的云端硬盘\stock"
```

### 2. 收盘后更新日线数据

建议在 A 股收盘后再执行：

```powershell
python update_daily.py
python backfill_turnover_rate.py
```

如果只是早上查看昨天收盘后的报告，也可以用昨天已经更新好的数据，不必重复跑。

如果确认只是历史回填、不会写入当天未收盘行情，才可以手工覆盖保护：

```powershell
python update_daily.py --force --end 2026-04-03
```

### 3. 更新财务评分和 LightGBM 预测

```powershell
python -m financial_rating --score-only --skip-report
python -m lightgbm_return_top3.daily_report
```

### 4. 生成正式质量报告

```powershell
python generate_quality_h20_report.py
```

报告会自动保存到：

```text
financial_data/reports/report_YYYY-MM-DD.md
```

如果当天已经生成过，会自动变成 `_2`、`_3`、`_4`，不会覆盖旧报告。

## 三、最新版报告怎么看

打开目录：

```text
financial_data/reports/
```

按文件名和修改时间找最新的：

```text
report_2026-07-02_7.md
```

报告里重点看这几块：

| 区块 | 含义 | 新手怎么用 |
|------|------|------------|
| 市场状态过滤器 | 判断大盘环境 | 如果是 `no_trade`，不要新开仓 |
| 可执行名单 | 个股层和市场层都允许时才出现 | 才能进入次日成交确认流程 |
| 观察名单 | 候选股票 | 只跟踪，不直接买 |
| 过热观察 | 20 日涨幅过高 | 不追高，等回撤或下次信号 |
| 可信度总排序 | 综合排序 | 用于复盘模型，不等于买入清单 |

## 四、Kronos 什么时候要跑

正式双模型报告需要：

- LightGBM 最新预测
- Kronos full H20 最新预测

检查 Kronos 是否过期，看这个文件：

```text
kronos_return_top3/output/mini_full_h20_lb512_predictions_latest.csv
```

如果里面的 `signal_date` 比 LightGBM 旧，正式报告会报错：

```text
双模型信号日不一致
```

这时需要跑全市场 Kronos：

```powershell
python -m kronos_return_top3 --predict-only --use-mini --hold-days 20 --full-universe --batch-size 32 --output-prefix mini_full_h20_lb512 --quiet
python generate_quality_h20_report.py
```

注意：全市场 Kronos 会对约 2700 只股票逐只预测，CPU 上可能需要几十分钟。

如果只是临时想看 LightGBM-only 报告，可以用：

```powershell
python generate_quality_h20_report.py --allow-lgbm-only
```

但这种报告会标注为临时版，不等同于正式双模型报告。

## 五、单支股票怎么预测

例如预测金海通：

```powershell
python predict_single_stock.py 603061.SH
```

也可以用股票名称：

```powershell
python predict_single_stock.py 金海通 --hold-days 20
```

如果想同时带上正式 LightGBM 截面排名：

```powershell
python predict_single_stock.py 603061.SH --with-lightgbm
```

单股报告会保存到：

```text
financial_data/reports/single_stock/
```

注意：单股 Kronos 只预测这一只股票，不能替代全市场 Kronos 排名。

## 六、怎么复盘历史报告

复盘 2026-06-12 报告的 Top3，截至 2026-07-02：

```powershell
python review_quality_report.py financial_data/reports/report_2026-06-12_2.md --as-of 2026-07-02 --top-n 3
```

复盘结果会保存到：

```text
financial_data/reports/reviews/
```

自动复盘会输出：

- T+1 开盘是否能买
- T+5、T+10、T+20 收益
- 最新收益
- 最大冲高
- 最大浮亏
- 92% 收盘止损是否触发
- `+20% 后回撤 8%` 止盈模拟
- `+15% 减半` 分段止盈模拟
- LightGBM / Kronos 预测误差

如果已经到 20 日持有窗口结束，可以加 `--final`：

```powershell
python review_quality_report.py financial_data/reports/report_2026-06-12_2.md --as-of 2026-07-13 --top-n 3 --final
```

## 七、几个关键词解释

### LightGBM

一个机器学习模型，用很多历史特征预测未来 20 日收益，并给全市场排名。

### Kronos

一个时间序列模型。本项目里有两种用法：

- 单股 Kronos：只预测一只股票。
- 全市场 Kronos：对股票池里每只股票逐只预测，再合并成全市场排名。

### H20

表示 20 个交易日预测窗口或持有窗口。

### 可信度

不是收益率，也不是成功概率。它是综合排序分，来自：

- 财务分
- 过去表现
- LightGBM 排名和预测收益
- Kronos 排名和预测收益
- 双模型方向一致性

### 待次日确认

不是当天买入。意思是如果下一交易日开盘满足跳空、涨停、成交量等条件，才进入纸面成交确认。

### 市场阻断观察

个股层满足条件，但市场状态过滤器是 `no_trade`。新手应理解为：只观察，不新开仓。

### 过热观察

股票短期涨幅太高，例如 20 日涨幅超过 25%。即使模型看好，也不要追高。

## 八、常见问题

### 1. 报告生成失败：双模型信号日不一致

原因：LightGBM 和 Kronos 的最新日期不同。

处理：

```powershell
python -m kronos_return_top3 --predict-only --use-mini --hold-days 20 --full-universe --batch-size 32 --output-prefix mini_full_h20_lb512 --quiet
python generate_quality_h20_report.py
```

如果只想临时看报告：

```powershell
python generate_quality_h20_report.py --allow-lgbm-only
```

### 2. 报告里可执行名单为空

常见原因：

- 市场状态是 `no_trade`
- 当天不是正式调仓日
- 候选股过热
- 双模型没有同时看多

这不是程序错，而是风控在阻断。

### 3. 为什么同一天有很多 `_2`、`_3`、`_4`

同一天重复生成报告不会覆盖旧文件，会自动加序号。

一般看修改时间最新、序号最大的那份。

### 4. 为什么 Kronos 预测少于股票池数量

少数股票可能停牌、缺少当天交易数据或历史数据不足，所以不会进入 Kronos 有效预测结果。

### 5. 能不能直接按 Top5 买

不建议。至少要看：

- 市场状态是否 `no_trade`
- 是否在可执行名单
- 是否过热观察
- 次日开盘跳空是否超过 3%
- 是否涨停或无成交
- 是否符合自己的仓位和风险承受能力

## 十、不要做的事

- 不要在 A 股交易时间内运行 `update_daily.py`；除非确认只做历史回填，否则不要使用 `--force`。
- 不要手工编辑 `daily_data/*.csv`。
- 不要手工编辑 `financial_data/scores.csv`。
- 不要把 `LightGBM-only 临时报告` 当正式双模型报告。
- 不要把 `观察名单`、`市场阻断观察`、`过热观察` 当买入清单。
- 不要直接删除旧报告，旧报告是复盘依据。

## 十一、文件速查

| 文件或目录 | 用途 |

## 十二、最小决策流程

看到一只股票前，按顺序问：

1. 市场状态是不是 `no_trade`？
2. 它在可执行名单里，还是只在观察名单里？
3. 它是不是过热观察？
4. LightGBM 和 Kronos 是否都为正？
5. 次日开盘跳空是否不超过 3%？
6. 如果买入，92% 收盘止损规则能不能严格执行？

任意一项不清楚，就先不做实盘动作，只记录观察和复盘。
