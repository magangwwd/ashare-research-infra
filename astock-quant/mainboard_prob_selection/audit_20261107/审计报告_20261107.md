训练代码 `02_train_predict.py:50` 和 `08b_train_v6_v7.py:41` 使用 `exit_date < 当次首个 signal_date`。按缓存重建了 28 个训练切点，未发现这一层的跨期标签泄漏。**时间滚动预测成立，不等于策略选择过程拥有未接触的测试集。**

本次没有重新下载或核对每条行情，也没有从原始日线重新构建面板或重训全部模型。因此，上述复现是“现有预测到结果”的复现，不是对原始行情、历史修订时点、训练产物来源的全面认证。原项目未提供依赖锁定文件、完整输入分区哈希和保存的季度模型，端到端复现仍有缺口。

## 发现及修复要求

严重度说明：P1 表示会改变策略定义、重要风险判断或破坏回测执行正确性；P2 表示统计口径、可追溯性或尚未触发的规则缺陷。修复优先级不表示本批收益均已受到影响。

### F01 · P1：前瞻脚本执行的模型更新规则与 V7 回测不同

位置：`09_weekly_signal.py:50–60`；对照 `02_train_predict.py:41–54`、`08b_train_v6_v7.py:33–43`。README 第 189 行已经承认这一待修问题，本次确认它确实改变输出。

回测按季度首个信号日冻结训练截止，前瞻脚本则以最新信号日重新训练四个模型，没有加载该季度的冻结模型。相同的 2026-11-02 信号日，季度缓存保护池第一名为 `CN.XSHG.600050`，集成分数约 0.606175；现存周度重训信号文件第一名为 `601788.SH`，分数约 0.583818。两者不是同一条已回测策略。

要求：先明确保留季度协议还是另立周度协议。若保留 V7，保存并复用季度模型，记录训练截止日、特征顺序、参数、库版本和模型哈希，并用历史信号回放验证候选及择时一致。周度协议必须另做相同频率的回测，不能直接承接季度版的绩效结论。

### F02 · P1：2024–2026“确认期”不能认证为未接触的独立确认集

位置：`README_全主板涨跌概率选股_20261107.md:30、77、109、124`；`08_improve.py:3、115、148–157`。

项目在前面的账户变体、保护池、持有期、止损与仓位比较中已经查看了 2020–2026 全期结果，随后才将 2024–2026 命名为确认期。08 的选择语句确实只读取 discovery 指标，但这一代码隔离不能消除先前全期探索对变体设计的影响。目录中也没有可独立核验、早于查看确认集结果的预登记记录。

因此，应将这一段改称“历史分段验证”，不能据此宣称已经取得独立样本外确认。这不是说季度模型训练直接使用了未来标签，而是策略开发与选择层面的重复使用数据问题。

V7 确认段只有 54 个择时开启且收益可计算的周，超额 t=1.675984；普通独立样本 t 假设下，单侧 p 约 0.0498、双侧 p 约 0.0996，均未包含研究选择的校正。“跑赢 96% 的 100 组随机账户”是条件随机基准的经验分位，不能直接解释成策略有 96% 的可靠性。

要求：冻结明确版本，将未来真正未观察的数据用于验收；预先固定主指标、比较基准、检验方向、观察期限与停止/修改规则。历史分段结果仍可保留，但需更正其证据等级。

### F03 · P1：最终 V7 的单笔账户损失被低估

位置：`README_全主板涨跌概率选股_20261107.md:198`；`results/improve_trades_V7_ensemble.csv`。

README 将 V7 的单笔最大账户损失描述为约 4.6%。实际最差交易为：

| 项目 | 数值 |
|---|---:|
| 股票 | CN.XSHE.002420 |
| 买入 / 卖出 | 2024-01-30 / 2024-02-02 |
| 交易前账户净值 | 136,890.359304 元 |
| 买入成本 | 68,125.748090 元 |
| 净亏损 | 11,255.971993 元 |
| 按持仓成本计的收益率 | -16.5223% |
| 按交易前账户净值计的损失 | **-8.2226%** |

交易前净值按 `100000 + 此前交易已实现盈亏之和` 重建。4.6% 不能作为最终 V7 的历史最差单笔账户损失。保护池的 ATR 阈值也不是未来损失上限；预算版没有执行 1% 风险仓位约束。

要求：从所选版本的交易表自动生成风险披露，统一使用交易前净值作分母，并将“计划风险”与实际损失明确区分。

### F04 · P1：延期卖出的处理允许时间倒序交易

位置：`06_protocol_backtest.py:81–102、114–132`；`03_backtest.py:108–109、135–167`。

当旧仓延期至周二，开盘在跌停而收盘可卖时，引擎先使用周二收盘卖出、置为空仓，再进入当天的新仓分支，按周二开盘价买入另一只股票。这将收盘后的现金和持仓状态用于当日开盘决策，违反事件顺序及“同时最多持有一只”的协议。

最小合成用例已复现：A 在 2026-11-03 收盘才退出，同一模拟中 B 却于 2026-11-03 开盘买入。证据见 `edge_case_evidence.json`。本批 V7 的 150 笔退出原因均为 `exit_close`，没有延期交易，**未发现该缺陷影响这批 V7 实际交易**；随机基准及其他未来样本仍需统一处理。

要求：按开盘、盘中、收盘依次推进事件，只有开盘前或开盘已完成退出才允许开盘新买入；保留成交时段字段，增加此边界回归用例。

### F05 · P2：Bonferroni 校正后的显著性表述错误

位置：`README_全主板涨跌概率选股_20261107.md:107`。

“约 30 个变体、t=2.45，粗略 Bonferroni 校正后处于显著边缘”不成立。即使用 331 个自由度作示例，单侧原始 p≈0.007402，乘 30 后约 **0.2220**；双侧校正约 **0.4441**。两者均超过 0.05。实际检验家族还应明确纳入已尝试的模型、仓位、退出、费用与筛选规则，不能只依赖 README 中不一致的“约20/30个”计数。

要求：更正文字，保存完整实验清单，预先定义检验家族。上述计算是对原表述的算术复核，不是对独立性或完整研究流程的统计认证。

### F06 · P2：重复运行可让信号文件与前瞻日志互相矛盾

位置：`09_weekly_signal.py:77–100`。

代码先覆盖 `signal_<日期>.csv`，之后才检查该周是否已经写入日志。若已经登记，日志保持旧值，信号文件却被刷新。合成用例中日志仍记 `FIXTURE_A`，同日期信号第一名已改成 `FIXTURE_B`。此外，“只追加”是逻辑上的行合并，实际通过重写整个 CSV 实现，没有原子替换或并发保护。

要求：先判重并核对内容；已经冻结的信号保持不变，修订应生成新版本与修订原因。保存完整候选快照、数据/模型哈希和生成时点，原子写入并处理并发。现有生产目录没有 `forward_log.csv`，不能认定已经开始形成可审计的前瞻记录。

### F07 · P2：前瞻脚本不拒绝过期日程或陈旧数据

位置：`09_weekly_signal.py:48–53、77–103`；`01_build_panel.py:156–160`。

脚本直接取缓存中最大的 signal_date，没有检查当前时点、计划入场是否已经过去，以及本次应有的信号日行情是否完整。现有 live 缓存最后信号为 2026-11-02，对应入场 11-03、退出 11-06。周末保留该历史文件本身正常，但脚本在错误时点或周一数据未更新时仍能将它作为本次信号处理；隔离用例也确认了过期入场被接受。

要求：依据交易日历计算本次预期 signal/entry/exit，检查数据覆盖及更新时间；过期数据拒绝生成可执行计划。历史回放应使用显式回放参数，并与真正的前瞻记录分开。

### F08 · P2：“周度”收益分组实际从周四开始

位置：`06_protocol_backtest.py:142–147`；调用方 `07_efficient_screen.py:172–174`。

NumPy 的 `datetime64[W]` 按周四为起点，不是本策略采用的交易周。示例：2026-11-02 至 11-04 归到 10-29 桶，11-05 至 11-06 归到 11-05 桶，一笔周二至周五持仓被拆成两段。

V0 全期相对 100 组随机账户均值的普通 t 值，按原分组为 2.4526，按周一至周日分组复算为 2.6255；V7 对应为 3.0443→3.1810。**这个修正没有改变 V7 的累计收益，也没有使其 t 值下降**，但原指标的周定义不正确。仍需另评估序列相关与多重比较；不能把修正后的普通 t 当成独立确认。

要求：以交易日历或 ISO 周明确分组，并按实际持有期设置统计单位。07 中将多个持有期相位的 t 值直接取平均，也只能作为探索摘要，不能视为正式合并检验。

### F09 · P2：先按周二可买性过滤，再排名，不符合固定前三名后备规则

位置：`08_improve.py:54、83–91`；`07_efficient_screen.py:65、126–134`；`03_backtest.py` 的主函数构造 weeks 处。

回测先根据周二行情生成的 buyable 过滤全池，再排名和决定首选股的 p_abs 门槛。这样可能把原排名第四名及之后的股票补进“前三名”，也可能在原第一名不可买时改变择时门槛。前瞻脚本则先给出信号日排名，再由执行者检查前三名，协议存在差异。

本次按信号日排名固定前三名、保留原首选股择时门槛，再逐只判断可买性，V7 的受影响周数为 **0**，累计收益差为 **0**。这是待修的逻辑缺陷，而不是本批 V7 已发现的收益偏差。

要求：将信号池、候选排名与成交条件按时间分开；固定排名后再模拟成交，并明确首选不可买时择时门槛是否随候选变化。

### F10 · P2：“费用×2”并未把所有费用翻倍

位置：`03_backtest.py:85–95`；`06_protocol_backtest.py:69`。

fee_mult 同时放大滑点与比例佣金，但不放大最低佣金、过户费或印花税。以 2026-11-06 的 50,000 元交易额为例，买入手续费 13.0→25.5 元，卖出手续费 38.0→50.5 元，不能称为全费用翻倍。

要求：改为准确标注的“滑点及比例佣金加倍”场景，或分别配置各成本项后重新输出敏感性结果。这里核验的是代码倍率含义，没有另行认证交易所及券商费率的适用情况。
